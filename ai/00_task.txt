Необходимо разработать максимально простой Web-сервер для отображения статического содержимого архивов без предварительной распаковки.

Подсказка: высока вероятность, что в архивах будет Allure-отчёт. Ориентируемся на него в первую очередь, но не ограничиваемся им.

Стек базируется на основе pom.xml

Требования:
* проект разрабатывается на Java 25 + Helidon SE 4.4 + Apache Common Compress;
* учитывай асинхронную работу с Helidon SE;
* проект должен поддерживать GraalVM Native Image;
* в архиве допускаются гигантские файлы; рекомендуется поточная передача файла;
* предварительная распаковка архива или его отдельных файлов строго запрещена;
* используй final и иммутабельные объекты везде, где это не приводит к последующему копированию памяти;
* используй ленивые вычисления везде, где это возможно;
* приложение конфигурируется с помощью командной строки;
* авторизация не нужна;
* шифрование не нужно;
* кеширование не нужно на этом этапе;
* БД запрещены;
* корректно выставляй HTTP заголовок Content-Type по расширению файла;
* логирование оставить минималистичным, без использования дополнительных зависимостей;
* использование методов, помеченных @Deprecated, запрещено.

Макет работы приложения:
* запуск осуществляется из терминала с указанием на некий архив (например, bundle.tar.gz, bundle.zip, bundle.tar.xz);
* в процессе запуска этот архив просматривается: для каждого файла регистрируется GET метод, с учётом расположения файла в архиве (вложенность необходимо сохранять и учитывать); если архив повреждён, то завершить работу приложения;
* при обращении к зарегистрированному файлу запускается новый процесс перебора всего содержимого архива;
* если обращений несколько, необходимо построить очередь (дублирующиеся запросы допускается объединять);
* перебор архива продолжается до тех пор, пока очередь не пуста;
* перебор архива не блокирует работу HTTP-сервера;
* в случае, если файл в архиве найден, то он отправляется целиком (но без распаковки во временный каталог; в идеале, если возможно, необходимо получить содержимое файла в виде потока на чтение и перенаправить его в поток на запись Helidon);
* при отсутствии файла возвращать 404;
* если архив повреждён, то завершить приложение;
* тесты не нужны (это будет отдельной задачей).

Конфигурирование приложения осуществляется с помощью CLI. Параметры:
* порт сервера (8080, если не указано);
* путь к архиву.

Техническая документация (в порядке убывания приоритета):
* (высокий приоритет) в Maven репозитории ~/.m2/repository/ доступны пакеты с исходными кодами зависимостей и их документация (`mvn dependency:sources dependency:resolve -Dclassifier=javadoc`);
* use context7;
* документация по Apache Common Compress --- https://commons.apache.org/proper/commons-compress/examples.html;
* тесты.

Используй все доступные источники информации для выявления @Deprecated методов в сторонних библиотеках.

Поддерживать все форматы архивов из Apache Common Compress не нужно. Достаточно: *.tar.gz, *.zip, *.tar.xz .

Замечание для OpenCode: ориентируйся на лимит в 100000 токенов.
